# K12 可评估测试集（来源：haolpku/K12-KGraph demo）

> **用途**：验证"上传文档 → 构建图谱 → 给一个问题能否定位到正确文档"的**完整功能链路**。
> 与 `graphrag_bench/` 不同（那套只有问题无答案），本套**每条问题都有答案和依据文档**，可严格计算检索命中率。

## 数据来源

- 上游：`haolpku/K12-KGraph`（NeurIPS 2026，教育知识图谱基准）
- 文件：`demo/sft_qa/math_primary_rjb_node.sample.jsonl`（577 条知识点问答）+ `edge.sample.jsonl`（400 条概念关系问答）
- 本目录由 2026-09-29 转换生成（去 \box/LaTeX 标记、转中文正文、每知识点成文档）

## 目录结构

```
k12_eval/
├── docs/                          # 509 篇知识点文档（.md，可直接上传）
│   ├── KG_秒.md                   # 每篇：知识点定义 + 相关提问示例
│   ├── KG_分钟.md
│   └── ...
├── questions_with_answers.csv     # 577 条评估清单（UTF-8 BOM）
└── README.md
```

## 评估清单字段

| 字段 | 含义 |
|---|---|
| `question` | 用户问题（输入） |
| `answer` | 标准答案（金标准） |
| `expected_doc` | **应被定位到的文档名**（=知识点名，即 ground truth） |
| `kind` | node（知识点问答）/ edge（概念关系问答） |

## 怎么评估（三步）

1. **上传文档**：把 `docs/` 下 509 篇全部上传（或抽样 50 篇），系统应完成切割+语义关联+图谱构建
2. **提问**：对每条 `question` 发起知识问答/检索
3. **判定**：系统返回的内容是否来自 `expected_doc` 对应文档 → 命中记 1，未命中记 0

**可计算指标**：
- **文档定位命中率** = 命中数 / 问题总数（核心指标，判断"能否找到正确答案所在的文档"）
- **答案语义匹配**：系统回答与 `answer` 的语义相似度（可用向量余弦）
- **跨文档推理**：kind=edge 的问题需要结合两个知识点，可验证图谱多跳关联能力

## 抽样建议

- 全量 509 篇 → 可做完整评测（推荐首次）
- 抽样 20~30 篇（如只选"时间/分数/图形"主题）→ 快速冒烟验证
- 注意：`KG_时间单位的换算.md` 与 `KG_时间单位换算.md` 是两个不同知识点文档（原数据如此），恰好可用来验证"语义相近文档能否被区分"

## 已知边界

- 知识点名含特殊字符时文档名做了替换（`/ \ : ?` → `_`），`expected_doc` 字段已同步
- 原数据中部分 `name` 重复（同一知识点多条问答），文档按 name 去重合并（取前 5 个答案句），问答对仍保留全部 577 条
- 内容是小学数学（时间/分数/图形/加减法），用于**功能验证**足够；如需领域匹配可另换语料，方法不变
