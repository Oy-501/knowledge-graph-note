# 判定算法的数学模型与假设

## 一、形式化

```
输入  c = (entity, description, keywords, domain, node_id)
四路  E = E_rule ⊕ E_kb ⊕ E_graph ⊕ E_web，每路是若干项 (kind, weight, positive)

score    = clamp(Σw, 0, 1)
decision = accept   当 score ≥ 0.80 且 ¬conflict
           reject   当 score < 0.35
           pending  其余
```

## 二、模型依赖的假设

任何模型都有成立前提。下面八条是这套模型的地基，
每条都注明**用什么检验**以及**在真实数据上的结论**。
结论来自正式库导出的 11 条真实候选与 30 条真实知识点。

### A1 可加性 —— 四路证据的贡献线性叠加，项间无交互

检验：`test_evidence_is_additive`，即 `Σw`（clamp 后）必须等于 `score`。
若实现里存在交互项或条件折扣，这个等式不成立，加权求和这种建模方式就作废。

**真实数据结论**：41 条真实语料全部成立。

已知边界：同一路内部存在互斥分支（标题形态是 if/elif，只会命中一条），
所以严格说是「路内择一、跨路相加」。这不破坏等式，但意味着
**同一路内的两个负向信号不会叠加** —— 一条又带编号又是谓语片段的标题，
只会被扣一次。

### A2 有界性 —— 证据强度存在上界，clamp 不损失排序信息

检验：真实数据里 `score == 1.0` 的比例（饱和率）。

**真实数据结论**：**0 / 11**，目前没有饱和。

风险：一旦候选质量整体提高，多条会同时挤在 1.0 而失去区分度。
届时需要把上界抬高或改为不 clamp 的排序值。

### A3 阈值静态 —— 0.80 / 0.35 不随领域、文档类型变化

检验：真实候选的**待审占比**。

**真实数据结论**：**90.9%（10 / 11 中的 10 条落在待审或该分支，其中 9 条 pending、1 条 reject）**。
也就是九成候选被推给人工队列。

这是本次最有分量的发现：模型本身没有错，但**静态阈值在当前语料上几乎不产生自动决策**。
若不同领域的最佳阈值本就不同，A3 不成立，则需要分级阈值或按领域标定。

### A4 冲突只否决、不额外加权 —— conflict 是 kb 路的二值副产品

检验：找出 `score ≥ 0.80` 而 `decision == pending` 的条目，唯一合法解释就是冲突位置起。

**真实数据结论**：**RAG，0.83 分，判为 pending** —— 冲突否决在真实数据上确实发生过。

风险：冲突目前只在加权里扣 −0.25，其余影响仅体现在「不许自动入库」。
若冲突本应更重，这个设计偏轻。

### A5 联网中性 —— 未命中或不可用 = 0 权重，不是负面证据

检验：领域专有名词不应因「搜不到」被驳回。

**真实数据结论**：**Memory 记忆模块，0.48 分，判为 pending**（未被驳回）。
这条性质有实际来历：早先把搜不到当作负证据，这类专有名词被批量误判驳回。

### A6 权重人工标定、不自适应

检验：目前**无法检验** —— 权重是人工设定的固定值，没有标注数据可校准。
用例 `test_weight_table_in_sync` 只保证代码与数据文件不漂移，
不保证权重本身合理。

**这是八条里最弱的一条。** 模型结论的可靠性受它直接限制。

### A7 输入完整性 —— entity / description 非空且形态正常

检验：真实候选里空描述的比例，以及异常形态（编号、谓语片段、重复实体）。

**真实数据结论**：描述为空 **0 条**；但存在
谓语片段（「注入」，真实判为 reject）与重复实体（「基础概念辨析」被抽出两次）。
说明脏输入确实会走降级分支，模型对它们的行为仍然自洽。

### A8 确定性 —— 相同输入 + 相同知识库状态 ⇒ 相同输出

检验：`test_same_real_input_is_deterministic`（连跑两次比对分数、决策与证据链）。

**真实数据结论**：成立。

风险：一旦引入缓存、时间戳或随机采样，这条失效，判定就不再可复现。

## 三、假设的强弱排序

| 假设 | 强度 | 依据 |
|---|---|---|
| A1 可加性 | 强 | 41 条真实语料等式全部成立 |
| A8 确定性 | 强 | 重复调用结果一致 |
| A7 输入完整性 | 较强 | 真实数据无空描述，异常形态按预期走降级分支 |
| A4 冲突否决 | 中 | RAG 一条实证，但样本仅 1 条 |
| A5 联网中性 | 中 | Memory 一条实证，样本仅 1 条 |
| A2 有界性 | 中 | 当前无饱和，但样本只有 11 条，不足以排除 |
| **A3 阈值静态** | **弱** | 待审占比 90.9%，静态阈值在真实语料上近乎不产生自动决策 |
| **A6 权重未校准** | **最弱** | 无任何数据支撑，纯人工设定 |

## 四、由此得到的两个建议

1. **A3 优先**：待审占比 90.9% 意味着这套判定在真实使用中主要是在**生成人工任务**。
   要么接受这个定位（判定只是排序与过滤，决策交给人），
   要么按领域重新标定阈值。当前数据不足以自动标定，但足以说明现状。
2. **A6 是天花板**：权重没有标注数据校准，任何"调优"都只是换一组同样没依据的数字。
   若想真正改进判定质量，需要先积累人工裁决结果作为标注集 ——
   `verdict_stage` 字段已经区分了 auto 与 human，正好可以充当这个标注来源。

## 五、样本量的诚实说明

11 条真实候选是很小的样本。上面所有带百分比的结论（尤其 90.9%）
只应当作**当前库的现状描述**，不足以外推。
随着候选增多，`verdict_real_corpus.json` 需要重新导出，
`test_production_record_is_consistent` 会在重跑时复核这些结论。
