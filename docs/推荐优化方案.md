> 编写时间：2026-09-03

## 1. 建议原则

1. **先修会让演示失败的主链路**（空图谱、无连线、上传重复节点、重排接口接错）。
2. **再收口信息架构**（左栏过载、筛选面板挡画布、空态与有数据态）。
3. **再做性能与工程卫生**（包体、重复前后端计算、死代码、端口约定）。
4. **最后才做协作 / LLM 问答 / 插件市场**——这些投入大，对毕设演示的边际收益低于主链路。

## 2. P0 · 必须先修（否则图谱「看起来没做出来」）

### P0-1 同文件内不推理连线（当前 14 节点 0 连线的根因）

**现象**：`POST /api/graph/build` 返回 14 节点、**0 条边**。

**代码事实**：

- `parser.parse_and_extract` 解析完会调用 `infer_links_for_new_file`。
- `infer_links_for_new_file` 只拿「**其它文件**」的旧节点当 `existing_nodes`：

```python
existing_nodes = db.query(Node).filter(
    Node.user_id == user_id,
    Node.file_id != file_id,   # 故意排除本文件
    Node.status == "active"
).all()
```

- `infer_links_batch` 是「新节点 × 已有节点」笛卡尔积，**不会做新节点两两配对**。
- 因此：**只上传一份文档时，永远不会产生连线。** 问答、学习路径、PageRank、断层分析全部退化。

**推荐改法**：

1. 推理时增加 **intra-file 配对**：同一 `file_id` 的节点两两打分（可限制窗口，例如相邻 N 段 / 同 heading，避免 O(n²) 炸库）。
2. `infer_links_for_new_file` 在 `existing_nodes` 为空时，仍应对 `new_nodes` 内部建边。
3. `can_connect` 已允许同文件，无需改窗口规则。
4. 对现有库提供一次 **「全量重排」真正重跑推理**（见 P0-2），把 14 个节点补边。

**验收**：只上传 `test_data/doc_A.txt`（或当前 `agent学习.txt`）后，`/graph/build` 的 `links.length > 0`，画布上能看到曲线。

---

### P0-2 「全量重排」前端调错接口

**现象**：控制面板「强制重排全量图谱」调用的是 `graphStore.rebuildAll()` → `POST /api/graph/build`，只是 **重新拉取已有数据**，不会删边、不会重推理。

**后端其实已有** `POST /api/graph/rebuild`（清空自动边后按文件顺序重推），前端 `graphAPI` **没有封装这个端点**。

**推荐改法**：

1. 在 `kg-vue3/src/api/index.js` 增加 `graphAPI.rebuild(weights, threshold)`。
2. `rebuildAll` 改为：先 `rebuild`，再 `build` 刷新本地 store。
3. 权重滑条 `onWeightChange` 目前只改本地粗细；应明确区分「改显示」vs「重新推理」，避免用户以为调 αβγδ 会立刻改边。

**验收**：点重排后，库中 `links` 数量变化；网络面板能看到 `/graph/rebuild`。

---

### P0-3 前端启动未稳定带出后端已有图谱

**现象**：后端已有 1 文件 / 14 节点，截图仍是「0 个知识点 · 0 个文件」空态。

**可能叠加原因**（按优先级排查）：

1. **首屏无加载态**：`fileStore.loadPersisted()` 是异步的，截图/用户第一眼永远先看到空态；失败时只 `console.warn`，界面无错误条。
2. **API 默认端口陷阱**：`api/index.js` 写死 fallback `http://localhost:8000/api`，而后端实际用 **8080**（`启动服务.bat`、`.env.development`）。一旦 `.env.development` 没被 Vite 读到，全站静默失败。
3. **`localhost` vs `127.0.0.1`**：页面在 `127.0.0.1:5173`，请求打到 `localhost:8080`。CORS 已覆盖 Origin，但建议 **API_BASE 与页面 host 策略统一**（或 Vite `server.proxy` 同源，彻底消灭 CORS）。
4. **`loadPersisted` 强依赖 `loadFromBackend().ok`**：图谱失败则 **文件列表也不拉**，左栏永远 0 文件。

**推荐改法**：

1. Vite `server.proxy`：`/api` → `http://127.0.0.1:8080`，前端 `VITE_API_BASE=/api`。
2. 启动页显示「正在从服务器恢复图谱… / 后端未连接」横幅，失败可一键重试。
3. 文件列表与图谱加载解耦：图谱失败仍展示文件。
4. `启动服务.bat`、`config.py PORT`、`.env.development`、文档里的 8000/8080 **统一成一张端口表**（建议：前端 5173、后端 8080）。

**验收**：刷新 `http://127.0.0.1:5173` 后 2 秒内，顶栏/左栏数字与 `/graph/build`、`/files` 一致。

---

### P0-4 上传路径会「再推一遍节点 + 再推理一遍」

**现象（逻辑缺陷，数据一大就会爆）**：

后端 `parse_and_extract` 已经：抽节点 → 向量化 → `infer_links_for_new_file` 落库。

前端 `fileStore.uploadFiles` 轮询拿到节点后，再 `graphStore.ingestNewNodes`：

- `this.nodes.push(...newNodes)`，**不去重**；
- 再调 `POST /knowledge/infer`。

若此时 store 里已经有 `loadFromBackend` 的同一批节点，画布会出现 **双倍节点**；连线也重复计算。

**推荐改法（二选一，推荐 A）**：

- **A. 前端上传完成后只 `loadFromBackend()`**（以后端为准），删除 `ingestNewNodes` 这条并行状态机。
- **B. 保留本地热更新，但必须按 `id` 合并，且不再调 infer**（推理以后端异步任务为准，轮询 `status=done` 后拉全图）。

轮询本身也可优化：现在每 2s 打 `/files/{id}/nodes`，偶发再打整个 `/files` 列表；应改为 **文件状态接口**（`status: parsing|done|error` + `node_count`），done 后再拉节点。

**验收**：上传 1 个文件，节点数 = 后端 `node_count`，刷新后数量不变。

---

### P0-5 解析质量：标题像整句，不像知识点

当前库标题样例（接口返回）：`LLM` 尚可，其余出现「一整段话当节点」、带编号的小节标题（如 `1. Memory 缓存模块`）混进实体。

无 LLM 时规则抽取可以保留，但需要 **硬约束**：

1. 实体名长度上限（建议 2–24 字），超长只当 `description`，不要当 `title`。
2. 丢弃纯序号 / 纯标点 / 过短（1 字）候选。
3. 优先 Markdown 标题、加粗术语、`（Abbr）` 模式；正文句子只抽主语。
4. 解析完成后在文件列表展示「抽到 N 个知识点」，并允许用户 **点进文件看抽取预览、删除垃圾节点**。

否则后面所有智能功能都建立在脏图上。

---

### P0-6 笔记 ID 类型分裂

- 前端离线创建：`note_lx8k_ab12` 字符串。
- 后端 `NoteSaveRequest.id: Optional[int]`。
- `createNote` 在后端成功时改成整数 id；失败时字符串 id 之后再 `POST /notes/save` 会 **422**。

**推荐**：全局笔记 id 以后端整数为准；离线草稿用 `localId` 字段，同步成功后替换。工作台 `linkedNodes` 与图谱节点 id（后端 int）比较时统一 `String(id)` 或统一 number，避免 `[[wikilink]]` 对不上。

## 3. P1 · 界面与交互（截图里已经能感到的问题）

### P1-1 左栏信息过载（最高优先级 UX）

`App.vue` 默认 `leftSections = ['files','control','analytics','review','qa']` **五项全开**。  
`ControlPanel.vue` 自身又有分组 / 隔离 / 四维权重 / 图例 / 校验 / 关联质量 / 异常 / 状态 / 健康 / 分组分布 / 插件……单文件约 **1500 行**。

截图结果：用户只看到上传区 + 分组 + 三条权重滑条；分析 / 回顾 / 问答全在折叠区下面，**新用户找不到**；δ 滑条看不到，但标题写「四维」。

**推荐信息架构**：

| 左栏模式 | 内容 |
|---|---|
| 默认「工作」 | 仅：上传 + 文件列表 + 简短统计（节点/边/孤立） |
| 「图谱调节」抽屉或二级页 | 分组、筛选、权重、重排 |
| 「洞察」Tab 或单独路由 | 分析仪表盘、每日回顾、知识问答 |

默认折叠：`['files']` 即可。控制面板默认只展开「分组」。权重收到「高级」。

### P1-2 画布被筛选面板挡住

`GraphCanvas` 左上角风格面板在 **有节点后常驻**：颜色 / 大小 / 文件夹 / 标签 / 关系 chips / 节点类型 / 强度滑条，`max-width: 260px`，会盖住力导向布局。

**推荐**：收成一个「筛选」按钮，展开才显示；关系/节点类型用下拉多选，不要一排 chip。

### P1-3 图谱画布缺少「找节点」

工作台左侧有搜索，**主图谱没有搜索定位**。`graphStore.searchNodes` 已存在，但 `title.toLowerCase()` 在 `title` 为空时会抛错。

**推荐**：画布顶栏搜索框 → 高亮并 `zoom.transform` 到该节点；`searchNodes` 对空 title 做兜底。文件夹下拉现在用截断 `fileId`，应显示 **文件名**。

### P1-4 空态与失败态

- 空态只说「去左侧上传」，没有「后端已有数据但没加载」的提示。
- 删除失败 / 解析超时 / 后端离线没有统一错误区。
- `FileUploader` 没有「清空全部」，但 `fileStore.clearAll` 已实现。

**推荐**：空态三按钮：上传示例文档、从服务器恢复、打开工作台写笔记。提供示例 `test_data/doc_*.txt` 一键导入（毕设演示极重要）。

### P1-5 导航 Tab 与视图一致性

截图里主区是图谱空态，视觉上「知识工作台」Tab 几乎与「知识图谱」同样醒目（`nav-tab.active` 只用浅底+雾蓝字，对比弱）。  
且工作台是 `v-show` + 懒加载，切换时 **没有路由**，刷新会丢当前视图。

**推荐**：加深 active 态；用 `vue-router`：`/` 图谱、`/workbench` 工作台，支持刷新停留。

### P1-6 移动端

`main.css` 在 768px 把左栏改到下方 `42vh`，但控制面板内容量仍无法用。毕设若需投影/笔记本窗口变窄，优先保证 **画布在上、左栏可完全收起**。

### P1-7 主题与背景默认值打架

`settingsStore` 注释写亮色默认，但 `background.value` 默认 `'dark_night'`。容易出现「亮色 UI + 暗色编辑器背景」割裂。统一默认：亮色 + `minimal` / `warm_sunset`。

## 4. P1 · 图谱渲染与性能

### P1-8 渐进式渲染是半成品

`GraphCanvas.render()` 写了 `useProgressive`（>200 节点分 5 批 `setTimeout`），但：

- 批次 timeout **不会取消**，`version` 连续 ++ 会叠多层 simulation；
- `watch(version)` 调 `render()`，`ingestNewNodes` 同时 `version++` 与 `restartTick++`，造成 **双触发**。

**推荐**：用 `requestAnimationFrame` 单飞行列；节点 > 500 时改 canvas / WebGL（或至少隐藏 label、降低 tick）；<200 保持 SVG。

### P1-9 力导向参数偏挤

`forceManyBody(-180)` + `linkDistance` 随 score 变短，节点一多容易团在一起。建议：按节点数量动态减弱电荷、提供「松/紧」一键，双击画布空白 `fit` 全图。

### P1-10 拖拽结束后坐标被清掉

`dragEnd` 里 `d.fx = d.fy = null`，用户排好的布局立刻被弹回。演示时很减分。应 **钉住拖过的节点**，提供「解除固定 / 重新布局」。

### P1-11 前端重复做图论

`KnowledgeAnalytics` 在主线程算 Brandes 介数、PageRank。节点 >300 才跳过介数，200 时已可能卡 UI。

**推荐**：Web Worker，或把报告放到后端；默认只算度中心度，点「生成报告」再算重活。

## 5. P2 · 架构与工程卫生

### P2-1 双前端、双入口，维护成本高

| 路径 | 角色 |
|---|---|
| `kg-vue3/` | **现行交付** Vue3 应用 |
| 仓库根 `index.html` + `app.js` + `styles.css` + 根 `vite.config.js` | 旧版 CDN D3 + Transformers 静态站 |
| `main.js` / `preload.js` / `server.js` | Electron 壳，容易指到错误入口 |

**推荐**：README / `启动服务.bat` 写死只启动 `kg-vue3`；旧前端移到 `_legacy/` 或删除，避免改错文件。Electron `loadURL` 对准 `5173` 的 Vue 应用。

### P2-2 计算职责重复

同一套能力在两边各写一遍：

- 向量：`kg-vue3/src/utils/vectorEngine.js`（还在 `index.html` **CDN 加载 Transformers.js**，首屏额外请求，模型可达数百 MB） vs `backend/.../vector_engine.py`（常降级 TF-IDF）
- 校验：`noteValidator.js` vs `services/validator.py`
- 窗口规则：`graphStore.canConnect` vs `inference.can_connect`

混合架构文档已写「计算在后端」。前端 Transformers **应改为按需**，默认不要 CDN 全局脚本。校验以一方为准，另一方只做展示。

### P2-3 Element Plus 全量注册

`main.js` 全量 `app.use(ElementPlus)` + 注册全部图标。对毕设可接受，但包体偏肥。后续用 `unplugin-vue-components` 按需引入。

### P2-4 超大组件拆分

优先拆：

- `ControlPanel.vue` → GroupPanel / WeightPanel / PluginPanel / HealthPanel
- `GraphCanvas.vue` → 渲染引擎 + 筛选条 + 抽屉
- `WorkbenchEditor.vue`（wikilink / ghost 层 / 关联弹窗）

### P2-5 后端接口契约

对照 `技术栈与功能实现清单.md` 与实现：

- 文档写 `PUT /files/{id}`，代码是 `PATCH`。
- 文档写 `GET /{id}/detail`、`DELETE /all`，代码里没有（前端 `clearAll` 是循环单删）。
- `DELETE /files/{id}` 找不到文件时仍 **HTTP 200 + `{ok:false}`**，前端不好区分。
- `POST /graph/build` 空 body 无 Content-Type 会 **422**（应用层没事，脚本/调试易踩）。
- 删除接口返回后再 `db.delete(file_record)`，若前面用了 `file_record.name` 还好；注意 session 过期对象。

建议补一层统一 `{ok, error_code, message}`，错误用 4xx。

### P2-6 数据层

- SQLite + JSON 存 embedding，无向量索引；节点上千后推理会慢。中期：PostgreSQL + pgvector，或至少把推理放进 `AsyncTaskQueue` 并给进度。
- `sim_topology` **恒为 0**（inference 里写了简化版未实现），四维权重 δ 对用户是空操作——要么实现邻居 Jaccard，要么 UI 隐藏 δ。
- `time_bridge` 在 `infer_links_for_new_file` 里 **一律 True**，时间桥语义被污染。
- 无用户系统：`user_id=1` 写死。协作（原 P2 规划）不要现在做；先保证单用户数据不丢。

### P2-7 测试与演示数据

没有自动化测试。最低配：

1. `inference` 单测：同文件两节点应出边。
2. `parser` 单测：给定 Markdown 标题应抽出短实体。
3. Playwright：上传 fixture → 画布节点数 > 0。

把 `backend/seed_demo.py` 做成启动可选 `--demo`，保证答辩当天 **打开即有 30 节点 + 连线**，不依赖现场上传和 LLM。

## 6. P2 · 功能层优化（现有功能「能用」变「好用」）

### 工作台

- `[[wikilink]]` 与图谱节点同步已有；缺：点击 `[[标题]]` 跳转节点抽屉、反向「哪些笔记链到我」。
- 智能推荐是词表启发式（`recommender.js`），与后端四维推理脱节。应对齐同一套 score，或标明「基于关键词命中」。
- 本地文件夹双写（File System Access API）很好，但浏览器权限失效时提示不够（`folderStore` 已有 re-grant 日志，应上升到 UI）。

### 问答 / 回顾 / 学习路径

- 问答是标题包含 + BFS，**0 边时关系问句必然失败**。先修 P0-1。
- 示例问句在无节点时仍是「JVM 和 GC」（与当前 agent/LLM 语料不符）；有节点时用度最高标题——若标题是整句，芯片会撑破布局，要截断。
- 间隔重复只存在 `localStorage`，换浏览器即丢失；应随笔记/节点存后端。
- 学习路径依赖 `prerequisite` 边；规则分类器若很少标这个类型，抽屉里会长期空白。需要在推理里提高前置关系召回，或允许用户手动标「A 是 B 的前置」。

### 插件

现在只有导出 JSON/Markdown、字数统计。不要先做「插件市场」。若要加，优先：**导出 PNG 图谱、导出学习路径 PDF**——都是答辩材料。

## 7. P3 · 明确可以后置

| 项 | 原因 |
|---|---|
| 多用户 / 权限 / 实时协作 | 需账号、冲突合并，超出当前单用户 SQLite |
| 接入大模型做抽取/问答 | 无 key 时主链路已断过一次；应作为可选增强，规则抽取要能独立演示 |
