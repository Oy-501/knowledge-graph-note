# 着色器（Shader）原理学习笔记

## 一、一句话定位

**着色器是运行在 GPU 上的小程序**。输入是顶点数据 / 纹理 / 全局参数（uniform），输出是"顶点该画在哪"与"每个像素该是什么颜色"。3D 画面里每个像素的颜色，最终都由一段着色器代码算出。

## 二、为什么会出现着色器：固定管线 → 可编程管线

早期 OpenGL 是**固定功能管线**：光照、雾化、纹理混合焊死在硬件里，只能调 API 参数。

可编程管线把最核心的两步开放给开发者：

| 阶段 | 运行次数 | 输入 | 输出 | 决定什么 |
|---|---|---|---|---|
| **顶点着色器** | 每个顶点 1 次 | 顶点位置/法线/UV | 裁剪空间坐标 | 物体"长什么样、在哪、怎么变形" |
| **片元着色器** | 每个像素 1 次 | 插值后的顶点属性 | 像素颜色 | 物体"表面看起来像什么" |

现代 GPU 上这两个阶段**成千上万个并行执行**（一个顶点/像素一个线程）——GPU 与 CPU 的本质区别就是**为海量小任务并行而生**。

## 三、渲染管线全景（一帧画一个三角形）

```
CPU 侧（每帧一次）:
  游戏逻辑/物理引擎更新世界状态
  → 上传顶点缓冲、索引、uniform（模型矩阵/相机矩阵/光源位置）、纹理
  → glDrawElements 发出绘制命令

GPU 侧（管线）:
  ① 顶点着色器 : 每顶点执行 → MVP 坐标变换 → 输出裁剪坐标 + varying
  ② 图元装配   : 顶点按索引连成三角形
  ③ 光栅化     : 三角形 → 像素（片元），对 varying 做透视矫正插值
  ④ 片元着色器 : 每像素执行 → 纹理采样/光照 → 输出颜色
  ⑤ 测试与混合 : 深度测试、透明度混合 → 写入帧缓冲 → 上屏
```

**关键认知**：顶点着色器只处理"点"，片元着色器只处理"像素"，中间隔着光栅化（三角形变像素的硬件步骤）。

## 四、顶点着色器：坐标变换

```
gl_Position = P × V × M × position
              投影   视图   模型
```

- **M（模型矩阵）**：物体在世界中的位置/旋转/缩放——**物理引擎的输出**（刚体 position/rotation 填进 M）
- **V（视图矩阵）**：世界坐标 → 以相机为原点的坐标
- **P（投影矩阵）**：3D 视野压成 2D 裁剪空间（透视近大远小）

顶点着色器还能做顶点动画（波浪、骨骼蒙皮、程序化地形）。

## 五、光栅化与插值：渐变从哪来

三个顶点颜色红、绿、蓝，三角形内部平滑渐变——这是**重心坐标（barycentric）插值**：

```
vColor = wA·红 + wB·绿 + wC·蓝    （wA+wB+wC = 1）
```

每个 varying（颜色/UV/法线）都被插值成每个像素自己的值；**透视下按 1/w 矫正**（透视矫正插值），否则纹理扭曲。

## 六、片元着色器：表面质感

1. **纹理采样**：`color = texture(uTexture, vUV)` —— 用 UV 取色
2. **光照**：`diffuse = max(dot(N, L), 0)` —— 法线·光源方向决定明暗
3. **后处理**：全屏三角形 + 片元着色器做模糊/泛光/描边/噪点

## 七、最小可运行示例（GLSL）

**顶点着色器**：

```glsl
#version 330 core
layout(location = 0) in vec3 aPos;      // 顶点位置（CPU 传入）
uniform mat4 uMVP;                       // P×V×M 合并矩阵（CPU 传入）
out vec2 vUV;                            // 传给片元着色器的 UV（varying）

void main() {
    gl_Position = uMVP * vec4(aPos, 1.0); // 坐标变换
    vUV = aPos.xy;                        // 顺带把 UV 传下去
}
```

**片元着色器**：

```glsl
#version 330 core
in vec2 vUV;                              // 光栅化插值后的 UV
uniform sampler2D uTexture;              // 纹理（CPU 绑定）
out vec4 FragColor;

void main() {
    FragColor = texture(uTexture, vUV);   // 采样纹理 → 像素颜色
}
```

## 八、与物理引擎的关系（游戏循环的两半）

| | 物理引擎（box2d-lite） | 着色器（渲染） |
|---|---|---|
| 运行在 | CPU | GPU |
| 每帧任务 | 更新刚体位置/速度（World::Step） | 把刚体位置画出来（顶点着色器） |
| 数据流向 | 输出 position/rotation | 填进 M 矩阵 → uniform → 顶点着色器 |

物理决定"世界此刻是什么状态"，渲染决定"把这个状态画出来"。

## 九、学习路径（按顺序）

1. **learnopengl.com** —— 经典免费教程（中文翻译齐全），从窗口创建到 PBR，主线教材
2. **The Book of Shaders**（thebookofshaders.com）—— 用 GLSL 做艺术，强化"像素思维"
3. **Shadertoy**（shadertoy.com）—— 看别人用一段代码画整个场景
4. 动手闭环：Three.js/WebGL 最小 demo（旋转立方体 + 片元着色器特效），理解"数据 → 着色器 → 像素"链路

**结合本项目**：知识图谱力导向图可以把节点位置计算搬到 GPU（顶点着色器），再用片元着色器给连线做发光描边。
