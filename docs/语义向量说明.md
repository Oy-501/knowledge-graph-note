# 语义向量（β 维）说明

本文说明 `inference.py` 四维打分里 **β 维（语义向量余弦）** 的实现、它为什么会静默失效、
以及怎么验证它真的在工作。

> 一句话：**词袋降级"还能用"是错觉。** 它不报错、不崩溃，只是把 β 维悄悄变成恒 0，
> 于是所有"关联为什么这么差"的排查都会绕开它。

---

## 1. 它在哪条链路上

```
上传文件 → parser 解析出节点 → embed_to_db 写向量
                                   ↓
                           kb_link 知识锚定（γ 维）
                                   ↓
        inference 四维打分：α 关键词 Jaccard + β 语义向量 + γ 知识库桥接 + δ 拓扑
                                   ↓
                                写入 links
```

β 的权重默认 **0.25**。它负责的是「**说法不同但是不是一回事**」——
这正是知识库桥接（γ）做不到的：γ 只能认出「知识库里有这个知识点」，
认不出「这句话换了个说法」。

两者是**互补**关系，不是替代关系：

| | 负责回答 | 依据 |
|---|---|---|
| γ 知识库桥接 | 知识上是否相关 | 知识库概念空间（有边界，未覆盖的内容不参与） |
| β 语义向量 | 说法不同是否同一件事 | 语义编码 |

## 2. 两种引擎

`app/services/vector_engine.py`

| | 真语义模型（首选） | 降级编码 |
|---|---|---|
| 触发 | 装了 `sentence-transformers` | 没装 / 加载失败 / `VECTOR_BACKEND=tfidf` |
| 实现 | `SentenceTransformer` 本地推理 | CJK 单字+二元组 + IDF + 带符号哈希 |
| 维度 | 384（从模型读，不写死） | 256 |
| 指纹 | `st\|<模型>\|<维度>\|<算法版本>` | `tfidf\|ngram\|256\|<算法版本>` |
| 能否认「换说法」 | 能 | **基本不能**（只认字面重合） |

### 降级编码的三个要点（都踩过）

1. **中文必须按字切词。** 曾经的实现按空白切词 —— 中文没有空格，整句话被切成 **1 个词元**，
   两个不同的中文句子共享 0 个词元，相似度**恒为 0**。
   现在连续汉字串切成相邻二元组：`数据库索引优化` → `数据/据库/库索/索引/引优/优化`。
2. **必须有 IDF。** 否则"的/了/是"这类高频词主导相似度。用整个语料统计文档频率，
   平滑 `idf = log((1+N)/(1+df)) + 1`；**整批向量共用同一张 IDF 表**，否则同批节点前后不可比。
3. **哈希必须带符号。** 纯 `idx = h % dim` 会让碰撞的两个无关词元互相**加正分**，凭空制造相似度。
   取哈希的一位做 `±1`，碰撞的期望贡献为 0。另外用次线性 TF（`1+log(tf)`）与 L2 归一。

## 3. 实测对比

### 对照集探针（`scripts/vector_probe.py`）

指标是**排序正确率**：每个改写对的相似度都必须高于对应无关对。

| | 旧降级 | 新降级 | 真模型 |
|---|---|---|---|
| 改写对平均相似度 | 0.064 | 0.161 | **0.688** |
| 无关对平均相似度 | 0.040 | 0.000 | 0.098 |
| **区分度（差值）** | +0.024 | +0.161 | **+0.591** |
| **排序正确率** | 2/8 | 6/8 | **8/8** |

> 旧降级那 2 分还是英文单词重合挣来的 —— 8 对中文改写句全部 0.000。

### 真实语料（171 节点、跨文件 11920 对）

| β 阈值 | 降级编码 | 真模型 |
|---|---|---|
| β ≥ 0.3 | 18 对（0.15%） | **933 对（7.83%）** |
| β ≥ 0.5 | 5 对（0.04%） | **123 对（1.03%）** |

约 **52 倍**。

### 单个节点对

- A：`索引失效是因为对列使用了函数`
- B：`如果给某列套了函数，索引就用不上了`

| 旧降级 | 新降级 | 真模型 |
|---|---|---|
| **0.000** | 0.175 | **0.778** |

证据行（`get_evidence`）只在 β > 0.6 时才追加「语义相似度 x.xx」——
所以这条连线在修好之前**永远不会有语义证据**，修好之后带上了 `语义相似度 0.84`。

## 4. 引擎指纹与陈旧向量（最容易漏）

不同引擎的向量**维度不同**。维度不同的两个向量做 cosine：

```python
if len(a) != len(b):
    return 0.0     # ← 这不是"不相似"，是"没法比"
```

如果换完模型不重建，库里旧向量还在，β 维会**静默失效**，
而且现象与"确实不相似"**无法区分**。所以：

- `nodes.embedding_meta` 记录每条向量的引擎指纹，**与向量成对写入**（体检会检查这一点）。
- `inference` 比对两侧指纹，不一致就**显式跳过并留 debug 日志**，不让 0 冒充"不相似"。
- 自检 `/api/system/doctor` 的「语义向量引擎」项报**陈旧条数**与维度分布。
- 换引擎后重建：

```bash
cd backend
py scripts/reembed.py --dry-run      # 先看现状
py scripts/reembed.py                # 重建全部
py scripts/reembed.py --tfidf        # 强制降级（验降级路径）
py scripts/reembed.py --db ../test_data/graphrag_bench/bench_result.db
```

**算法改动要 +1 `ALGO_VERSION`** —— 这样即便还在用降级实现，旧向量也会被识别为陈旧。

## 5. 安装与网络

```bash
# ① 先装 CPU 版 torch。PyPI 上 Windows 的 torch 默认带 CUDA（约 2.5GB）；
#    本项目只用 CPU 推理，CPU 版约 200MB。
py -m pip install torch --index-url https://download.pytorch.org/whl/cpu
# ② 再装其余（pip 不会再替换已装好的 torch）
py -m pip install sentence-transformers
```

**模型选择必须匹配内容语言。** `all-MiniLM-L6-v2` 是**纯英文**模型，
用它编码中文等于随机向量 —— 本项目默认用
`paraphrase-multilingual-MiniLM-L12-v2`（384 维，中英都行）。

**HuggingFace 官方站在本机不可达**（`curl https://huggingface.co` → 000），
`hf-mirror.com` 可用（→ 200）。所以：

- `app/config.py` 的 `HF_ENDPOINT` 默认 `https://hf-mirror.com`，引擎启动时会设成环境变量
  （**必须在导入 sentence-transformers 之前设**）。
- 权重缓存到 `backend/models/`（`VECTOR_CACHE_DIR`），下好一次之后可离线运行。
  该目录已加进 `.gitignore`（约 470MB）。
- 已下好模型、要断网运行：`HF_HUB_OFFLINE=true`。

## 7. 怎么验证它在工作

```bash
cd backend
py scripts/vector_probe.py            # 排序正确率与区分度（应为 8/8、+0.5 以上）
py scripts/vector_probe.py --tfidf    # 对比降级水平
py scripts/reembed.py --dry-run       # 是否有陈旧向量
```

体检里还有一项「**语义向量接线**」守三条不变量：

1. 降级编码按字切词 —— **实际调用 `analyze()` 看词元数**，不做字符串匹配；
2. `embedding` 与 `embedding_meta` 成对写入（AST）；
3. 连线标记不得硬编码 —— 先行为验证 `_link_flags`，再扫 `Link(x=True)`
   与 `{"x": True}` **两种写法**。

> 第 3 条的第二种写法是**反向验证抓出来的**：只扫关键字参数时，
> 把标记写死成 dict 字面量仍然全绿（漏报）。

## 8. 一个必须记住的度量陷阱

看统计量之前，先确认这个字段**不是硬编码的**。

实例：`inference` 曾经把所有自动生成的连线写死 `time_bridge=True`，于是
「时间桥接 553 / 语义桥接 11」量的是**哪段代码写的**，不是「依据是什么」——
拿这个数字推断「语义路径没出力」会被彻底带偏。数字本身没问题，是字段没有语义。

**规则**：任何表示"依据 / 来源 / 类型"的标记，都必须由依据推导；
写死的标记会让所有依赖它的统计量失去意义。

## 9. 已知遗留

- 库里**已有的**连线仍是旧标记（`time_bridge` 全 1），要重跑推理才会刷新。
- `semantic_bridge` 这个字段名在后端指「知识库桥接（γ>0）」，
  而在前端 `graphValidator.js` 里指「孤儿收养桥接」—— **同名不同义**，
  图表里两类连线会共用同一种样式。彻底解决需要拆成两个字段，
  涉及前端渲染与既有数据，暂未动。
