> 适用项目：`Oy-501/knowledge-graph-note`（知识图谱笔记系统）
> 文档性质：**可持续回归的测试方案**（区别于《基准语料测试报告.md》——那份是一次性实测记录）
> 更新日期：2026-09-29
> 配套数据：`test_data/`（graphrag_bench 链路语料、k12_eval 检索语料、kb_demo 中文知识库样例）

## 一、测试目标与范围

本方案围绕项目的**核心承诺**设计用例，任何一次回归都必须保证这些承诺不倒退：

| 核心承诺 | 对应模块 | 验收要点 |
|---|---|---|
| 图谱不允许孤立节点（Degree=0） | `graph` / `inference` | 上传任意文档后孤立节点数必须为 0 |
| 新文件触发全量旧节点重排 | `graph.rebuild` / `files.upload` | 上传新文件后旧节点间出现新连线 |
| 未来知识回溯关联旧文件 | `inference` / `graph.update` | 跨文件语义桥接可解释、可溯源 |
| 删除文件 = 删除其全部节点与连线 | `files.delete` | 删除后画布无残留、计数归零 |
| 知识点自测与纠错 | `knowledge.validate` / `notes.validate` | 四路证据判定 ≥0.80 accept、<0.35 reject |
| 大文件切割与分片追溯 | `file_splitter` | 超阈值自动分片，分片归属原文件 |
| 多文件关系无错、可查证 | `graph` / `kb.graph` | 关系类型、桥接依据、来源文档可追溯 |

**范围**：后端 11 个 API 模块（auth / files / graph / kb / knowledge / notes / summary / profile / system / admin / audit）+ 前端图谱渲染交互。不包含 Electron 壳（已归档 legacy/）。

## 三、核心承诺验收用例（每次回归必跑）

### TC-C1 零孤立节点

| 项 | 内容 |
|---|---|
| 前置 | 独立库 + 后端就绪 |
| 步骤 | ① 上传 `kb_demo/前端工程实践.txt` ② 等待 `status=done` ③ 调 `GET /graph?include_discarded=true` |
| 预期 | 图谱中不存在 `links.length === 0` 的节点 |
| 判定 | 孤立节点数 = 0，否则 FAIL（孤儿收养未生效） |

### TC-C2 跨文件语义桥接

| 项 | 内容 |
|---|---|
| 前置 | 完成 TC-C1 |
| 步骤 | ① 再上传 `kb_demo/技术选型讨论.txt` ② 调 `GET /graph` |
| 预期 | 两文件节点间出现连线，且 `source_file != target_file` 的连线数 ≥ 1 |
| 判定 | 跨文件连线存在 + 任一连线可展示依据（来源片段/知识库桥接句） |

### TC-C3 全量重排（旧节点间新连线）

| 项 | 内容 |
|---|---|
| 前置 | 完成 TC-C2，记录此时连线集合 L1 |
| 步骤 | ① 上传 `kb_demo/服务端接口设计.txt` ② 调 `POST /graph/rebuild` ③ 再取连线集合 L2 |
| 预期 | L2 包含旧节点（A、B 文件）之间新增的连线 |
| 判定 | `L2 \ L1` 中至少 1 条连线的两端都来自旧文件 → 全量重排生效 |

### TC-C4 删除语义 = 删上传不删本地

| 项 | 内容 |
|---|---|
| 前置 | 完成 TC-C2（库中有 ≥2 个文件） |
| 步骤 | ① 记录当前节点数 N1、连线数 L1 ② `DELETE /files/{file_id}`（删其中一个文件） ③ 调 `GET /graph` |
| 预期 | 该文件产生的所有节点与连线消失；本地源文件仍存在 |
| 判定 | 节点数 ≤ N1、连线数 ≤ L1，且被删文件 id 不再出现在任何节点/连线中；本地文件未被删除 |

### TC-C5 知识点自测与纠错

| 项 | 内容 |
|---|---|
| 步骤 | ① `POST /knowledge/validate`（提交一条正确知识点）② 提交一条明显错误知识点 |
| 预期 | 正确知识点 ≥0.80 accept；错误知识点 <0.35 reject 或进入人工队列 |
| 判定 | 响应含 verdict + score + 证据来源（四路证据：知识库/图谱/文本规则/联网） |

### TC-C6 检索质量（文档定位命中率）

| 项 | 内容 |
|---|---|
| 前置 | 将 `k12_eval/docs/` 抽样 30 篇上传（或全量 509 篇） |
| 步骤 | ① 取 `k12_eval/questions_with_answers.csv` ② 逐条发起检索/问答 ③ 判断返回内容是否来自 `expected_doc` |
| 判定 | 命中率 = 命中数/提问数；≥80% 记为 PASS，<80% 记录失败问题清单 |
| 备注 | edge 类问题单独统计，验证跨文档多跳能力 |

## 四、按模块的稳定用例

### 4.1 认证与权限（auth / admin）

| 用例 | 步骤 | 预期 |
|---|---|---|
| AU-1 登录链路 | POST /auth/login → GET /auth/me | 200；me 返回当前用户 |
| AU-2 未授权拒绝 | 不带 X-Admin-Token 调 admin 接口 | 401，不返回数据 |
| AU-3 错误口令 | 传错 ADMIN_TOKEN 上传文件 | 401「需要登录」（写守卫生效） |
| AU-4 口令强度 | 注册弱口令 | 400 明确提示 |

### 4.2 文件上传与解析（files）

| 用例 | 步骤 | 预期 |
|---|---|---|
| FL-1 正常上传 | 上传 kb_demo/*.txt | 200，status=parsing（异步）→ 轮询转 done |
| FL-2 空文件 | 上传 0 字节文件 | 400「文件内容为空」 |
| FL-3 二进制伪装 | PNG 魔数改名 .txt | 415「检测到二进制内容」 |
| FL-4 超大文件 | 将上限调低后上传超限文件 | 413/400 明确拒绝，连接不挂死 |
| FL-5 删除恢复 | 删除后重新上传同名文件 | 可重新解析，无残留幽灵节点 |
| FL-6 文件列表 | GET /files | 文件状态/节点数/时间与库一致 |

### 4.3 图谱构建与更新（graph / inference）

| 用例 | 步骤 | 预期 |
|---|---|---|
| GR-1 构建 | POST /graph/build | 节点/连线计数正确，孤立 = 0 |
| GR-2 增量更新 | POST /graph/update | 新节点融入，旧节点位置微调（时间桥接属性） |
| GR-3 强制重排 | POST /graph/rebuild | 全部节点重算，无节点甩出画布边界 |
| GR-4 关系分类 | 检查连线 type 分布 | 五类（related/theory/prerequisite/implementation/extension）+ 桥接类型可区分 |
| GR-5 孤儿收养 | 构造孤立场景（新概念无相似词） | 自动挂灰虚线到 Top5 中心度节点，w2=0.3 |

### 4.4 知识库（kb）

| 用例 | 步骤 | 预期 |
|---|---|---|
| KB-1 统计 | GET /kb/stats | entries/relations/coverage_rate 与库一致 |
| KB-2 条目 CRUD | POST→PUT→DELETE /kb/entries | 增删改查闭环，关系随之更新 |
| KB-3 关系管理 | POST /kb/relations → DELETE | 关系建立/解除，无幽灵边 |
| KB-4 导入 | POST /kb/upload + /kb/imports | 导入状态可查，词条进入匹配池 |
| KB-5 匹配 | POST /kb/match | 返回匹配条目 + 置信度，未覆盖内容落在边界外 |

### 4.5 知识点判定与搜索（knowledge / notes）

| 用例 | 步骤 | 预期 |
|---|---|---|
| KN-1 判定 | POST /knowledge/validate | 四路证据均有来源，阈值生效 |

## 五、边界与安全用例（SA 系列）

| 用例 | 步骤 | 预期 |
|---|---|---|
| SA-1 注入防护 | 文件名/知识点含 `../`、`;`、SQL 片段 | 被转义或拒绝，不落盘、不执行 |
| SA-2 越权 | 普通用户访问 admin 接口 | 403/401 |
| SA-3 并发上传 | 同一文件并发 10 次上传 | 不重复入库（去重）、无资源竞争报错 |
| SA-4 空库操作 | 无文件时调 graph/build、kb/stats | 200 + 空结果，不报 500 |
| SA-5 异常恢复 | 上传中途杀后端 → 重启 | 状态可恢复为 failed 或重新解析，不卡 parsing |

## 七、执行流程与通过标准

### 7.1 执行顺序

```
准备环境（独立库）→ 核心承诺回归（TC-C1~C6，必跑）
→ 模块用例（4.1~4.7 全跑）→ 边界安全（SA 全跑）
→ 性能压力（PF 按需）→ 汇总报告
```

每次回归**至少**跑完 TC 系列 + 4.1~4.5 模块用例；版本发布/大改动时跑全套。

### 7.2 通过标准

| 级别 | 标准 |
|---|---|
| 阻断（Block） | TC-C1~C4 任一 FAIL、接口 500、数据丢失 |
| 严重（Major） | TC-C5/C6 未达阈值、删除残留、审计缺失 |
| 一般（Minor） | 文案/样式/响应延迟超标但不影响功能 |
| 通过门槛 | 阻断 = 0、严重 ≤ 2 且均已记录处理方案 |

### 7.3 结果记录

- 每次回归输出 `test_data/selftest/regression_<日期>.json`（结构化结果：用例 id、PASS/FAIL、耗时、失败详情）
- 失败用例必须写清：步骤、实际结果、期望结果、根因、修复后重跑结果
- 通过门槛未达标时**不得**向上游宣称"测试通过"

## 九、已知限制与待办

1. **语义链路依赖**：`sentence-transformers` 未安装时向量引擎降级 TF-IDF，TC-C2/C5/C6 的预期会受影响——回归前确认 `requirements.txt` 依赖已装，或记录降级运行。
2. **自动采纳率**：历史回归自动采纳为 0（阈值 0.80），大量候选堆积人工队列——若回归中出现，记为 Major 并复核阈值配置。
3. **前端自动化**：当前用例以 API 为主，前端图谱交互（缩放/拖拽/悬浮溯源）建议每轮人工过一遍 TC-C1~C4 对应界面；有浏览器自动化能力后可补充 UI 用例。
