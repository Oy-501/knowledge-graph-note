## 五、发现的问题与限制

### 1. 正式库图谱为空（最需要处理）

`build_summary` 返回 **11 节点 / 0 连线**。四维关联、知识库桥接、图谱总结的代码均存在且测试通过，但当前正式库没有可观察的边。

建议：对现有文档重新执行解析与关联重建（`scripts/kb_build.py --reparse` 或后台「重建关联」），再复跑本审计。

### 2. 两个主题未 confirmed，不是缺陷

- `光合作用`、`数据库索引` → `unverified`：检索结果未达到「多源 + 精确命中」门槛；
- `TCP 拥塞控制` → `probable`：仅 2 个独立域名，且未提供描述做一致性校验。

机制刻意保守：**搜不到不等于不存在**，因此不上调为 confirmed。

### 3. 前端若干功能是本地实现

Q&A、时间线、网络分析、插件系统、主题工作室都在浏览器内计算，不落后端。换设备或清缓存后这些状态不保留；如果要求跨设备同步，需要新增持久化端点。

### 4. 审计脚本踩到的框架差异

新版 FastAPI 的 `app.routes` 里，`include_router` 生成的是 `_IncludedRouter`（**没有 `path` 属性**），直接遍历会误判「全部端点缺失」。正确做法是用 `app.openapi()["paths"]`。
