# 阈值实验：知识库未命中的候选能否被采纳

## 背景

对照 RAG（Lewis et al., 2020）提出猜想：现行评分把"知识库命中"设为必要条件，
导致知识库外的真实概念永远无法自动采纳。本实验用真实候选回放四种评分口径验证。

先看权重结构（取自 `knowledge_verifier.py`）：

| 维度 | 满分 | 说明 |
|---|---|---|
| 文本规则 | 0.48 | 0.25 + 0.08 + 0.10 + 0.05 |
| 知识库 | 0.55 | 0.30 + 0.15 + 0.10；**未命中时扣 0.05** |
| 图谱 | 0.15 | 0.10 + 0.05 |
| 联网 | 0.15 | confirmed 上限 |

无知识库命中时理论上限 = 0.48 + 0.15 + 0.15 − 0.05 = **0.73**，低于采纳阈值 **0.80**。

## 方法

1. 取全部有判定结果的候选，排除压测数据（`测试概念N`）
2. 只保留无知识库命中的，按实体去重（同一文档多次上传会产生完全重复的候选）
3. 每种口径用存储的证据重算分数，不改动数据库
4. 人工标注"是否为真实可用的技术概念"

### 四种口径

| 口径 | 分数 | 阈值 | 含义 |
|---|---|---|---|
| A | 原分 | 0.80 | 现行逻辑 |
| B | 归一化 | 0.80 | 知识库缺失时按剩余维度满分 0.78 折算 |
| C | 原分 | 0.70 | 只降阈值 |
| D | 归一化 | 0.70 | 同时改刻度与阈值 |

归一化定义：`score / cap`，其中 `cap = 0.48 + 0.15 + 0.15 + (0.55 if 命中知识库 else 0)`，
截断到 1.0。即把"结构上不可用的维度"从分母里剔除，而不是让它当成 0 分。

## 结果

样本 19 条（去重后），其中真实概念 15 条、抽取残骸 4 条。

| 口径 | 采纳数 | 精确率 | 召回率 |
|---|---|---|---|
| A 现行 0.80 | 0 | — | 0% |
| B 归一化 0.80 | 0 | — | 0% |
| C 原分 0.70 | 0 | — | 0% |
| **D 归一化 0.70** | **4** | **100%** | **27%** |

D 捞回的 4 条：`API`（0.72）、`为什么数据库索引选择 B+ 树`（0.74）、
`JWT 无状态认证`（0.74）、`JWT 的存储位置风险`（0.74）——全部为真实概念。

## 结论

1. **猜想一成立**：现行口径下，15 条真实概念**一条都无法自动采纳**（召回 0）。
   这不是"判定严格"，而是分数上限 0.73 与阈值 0.80 之间没有通路。
2. **单点修改无效**：只降阈值（C）仍为 0，因为原分最高只有 0.58；
   只做归一化（B）也为 0，因为折算后最高 0.74 仍低于 0.80。
   必须同时处理"刻度"和"阈值"。
3. **D 口径在本样本上无误收**（精确率 100%），但召回仅 27%。

## 局限

- 样本只来自 2 份文档（LLM 基础、Web 缓存与 JWT），共 19 个独立实体，**不足以定阈值**。
- 标注人为系统作者，存在主观偏差；`Memory 记忆模块` 这类"模块名算不算知识点"本身有争议。
- 假样本分数集中在 0.00–0.48，真样本集中在 0.38–0.58，两者重叠区窄，
  这可能是样本偏差（噪音标题恰好都很短），换语料后重叠会变大。

## 建议

不直接改线上阈值。先做**影子评估**：D 口径的判定只写日志不入库，
积累 2–3 份新文档后再看精确率是否守住，再决定是否切换。

```bash
cd backend
py scripts/recall_experiment.py --sample 100   # 抽样 + 联网复核，写 sample.json

```
