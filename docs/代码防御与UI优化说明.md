# 代码防御机制与 UI 优化说明

> 目标：让「代码错误」要么在启动前就被发现，要么发生时不扩散、不静默、可追溯。
> 同时修掉 UI 上真实存在的可读性与可达性缺陷。
>
> 本文档描述本轮实际落地的内容与实测结果，不含规划中的未实现项。

---

## 一、防御机制：四层防线

错误的发生位置决定了该在哪一层拦。四层从「写代码时」到「崩了以后」逐层收紧：

```
① 开发期静态防线   体检脚本：语法 / 导入 / 路由冲突 / 表结构漂移 / 静默吞异常
② 运行期后端兜底   全局异常处理器 + request_id + 慢请求告警 + 5xx 落审计
③ 数据与边界守卫   分页守卫 / 文本与整数守卫 / 业务异常语义化
④ 前端防线         全局错误处理器 + 错误边界 + 请求层重试与分类 + 错误上报
```

---

## 二、第 1 层：开发期静态防线

### 一键体检

```
体检.bat                      # 或：py backend/scripts/check.py
py backend/scripts/check.py --json    # 机器可读，供自动化使用
py backend/scripts/check.py --build   # 附带跑一次前端生产构建（较慢）
```

退出码 0 = 可启动；1 = 存在必须修复的错误。

### 七项检查与「为什么值得查」

| 检查 | 能抓到的真实问题 |
|---|---|
| 语法编译 | 缩进/语法错误（用内置 `compile()` 纯内存校验，不落盘，跨平台一致） |
| 应用导入 | 循环导入、缺依赖、名字拼错 |
| 路由注册 | **同一「方法+路径」注册两次** —— 后者静默覆盖前者，接口行为与代码不符却无任何报错 |
| 接口契约 | OpenAPI 生成失败（响应模型标注有误时 `/docs` 与前端类型推导会一起挂） |
| 表结构一致性 | **模型加了列但忘了写迁移** → 运行期报 `no such column`，极难定位 |
| 静默吞异常 | `except: pass` —— 错误被藏起来，排查时无线索 |
| 关键配置 / 前端工程 | 默认口令未改、阈值倒挂、目录不可写、关键文件缺失、依赖未装 |

### 本轮由它抓出的真实问题（4 个）

1. **上传目录路径解析不一致** —— `main.py`（静态挂载）与 `profile.py`（写入）各自用
   `dirname(dirname(__file__))` 推算，因文件层级不同（`app/` 与 `app/api/`）算出
   `backend/uploads` 与 `backend/app/uploads` 两个目录。
   后果：头像/背景图可能**存到 A 处而静态服务挂在 B 处 → 上传成功但访问 404**。
   修法：统一为 `settings.resolved_upload_dir` 单一事实来源，并让体检校验两者一致。

2. **`except: pass` 共 11 处**，其中一处很危险：`vector_engine.encode_batch` 中
   向量模型编码失败时静默降级为 TF-IDF。后果是同一批节点「一部分模型向量、
   一部分 TF-IDF 向量」，维度不同时余弦相似度直接返回 0，**关联质量静默失效且毫无痕迹**。
   修法：11 处全部补上日志（必要的用 `debug`，向量降级用 `warning` 并禁用坏掉的编码器）。

3. **分页参数未防负数**（详见第 3 层）。

4. `py_compile` 在 Windows 下写 `os.devnull`（`nul`）失败，导致体检脚本自己报错
   —— 防线本身不可信最糟糕，已改为 `compile()`。

## 三、第 2 层：运行期后端兜底

### request_id 贯穿全链路

每个请求分配 `X-Request-ID`（12 位），同时出现在：

- 响应头 `X-Request-ID` / `X-Elapsed-Ms`
- 响应体的 `error.request_id`
- 服务端日志前缀 `[rid]`
- 操作审计的 `detail.request_id`

用户只需报一个 ID，就能从审计日志还原完整现场。

### 全局异常处理器（4 个）

| 处理器 | 行为 |
|---|---|
| `AppError` | 业务异常，直接返回 `message` + `hint` |
| `HTTPException` | 结构化返回，**保留 `detail` 字段**兼容老前端 |
| `RequestValidationError` | 把 Pydantic 错误翻成「哪个字段、错在哪」（`detail.fields`） |
| `Exception` | 最后一道网：任何未捕获异常 → 结构化 500，**不再是裸 500 或空响应** |

响应统一形状：

```json
{
  "ok": false,
  "error": {
    "code": "schema_mismatch",
    "message": "数据库结构与代码不一致",
    "hint": "运行 `体检.bat` 查看缺列，并在 _COLUMN_MIGRATIONS 补 ALTER 语句。",
    "request_id": "e0b3f983e4bc",
    "path": "/api/xxx",
    "detail": { "...": "..." }
  }
}
```

### 「异常 → 人话」映射（`services/errors.py`）

不只给错误码，还给**下一步怎么做**：

| 异常 | 提示 |
|---|---|
| `IndexError` | 数据越界 —— 这属于程序缺陷，已记录现场；请反馈 request_id |
| `KeyError` | 缺少必要字段，请补齐后重试 |
| `no such column` | 表结构与代码不一致 → 去跑体检并补迁移 |
| `database is locked` | 有重建/解析任务在写库，等它跑完；长期如此改用 PostgreSQL |
| `disk I/O error` | 检查磁盘空间与权限 |
| `out of memory` | 数据量超内存，拆分文件或调低 `MAX_*` 上限 |

**判定顺序有讲究**：报文关键字规则先于异常类型规则。
反例（真实踩到）：`sqlite3.OperationalError("no such column: ...")` 会先命中
类型规则 `OperationalError` → 被误报成「数据库被占用」，而真实原因是表结构漂移。
越具体的判断越要放前面。

### 5xx 落审计

未捕获异常除写日志外，还会写一条 `action="server_error"` 的审计记录
（含 method / path / query / 异常类型 / 原始信息 / 建议），
**「后台管理 → 操作审计」可直接看到服务端错误现场**，不必去翻控制台。

### 慢请求告警

超过 3s 的请求写告警日志（`/api/health` 除外），用于提前发现性能退化。

## 四、第 3 层：数据与边界守卫

### 分页守卫（真实缺陷修复）

各接口此前写的是 `.limit(min(limit, 200))` —— 只防上限，**没防负数**。
而 SQLite 的语义是：

```
LIMIT 5  → 5 条
LIMIT -1 → 300 条   ← 等价于「不限制行数」
```

实测证明（内存库 300 行）：`LIMIT -1` 返回全部 300 条。

因此 `?limit=-1` 会让 `min(-1, 200) = -1` → **整张表返回给客户端**：
既慢（上万条审计日志）、又可能造成数据外泄。`OFFSET` 负数则被静默当 0。

修法：`clamp_paging(limit, offset, max_limit, default_limit)`
把非法值收敛到安全区间（而不是报错——分页参数属于「怎么给都能用」，静默收敛更友好）。
已在 8 处调用点统一替换。

实测：

| 请求 | 修复前 | 修复后 |
|---|---|---|
| `limit=5` | 5 条 | 5 条 |
| `limit=-1` | **整表** | 默认 30 条 |
| `limit=100000` | 200 条（此项原本就对） | 200 条 |
| `limit=-1&offset=-5` | 整表 | 30 条 |

### 其他守卫工具

`require_text` / `require_int` / `GuardError` / `safe_detail`
—— 供「用户可控内容写库」与「回传细节」的入口使用；`safe_detail` 会对
`token`/`password`/`secret` 之类键名自动脱敏，并裁剪超长内容。

## 五、第 4 层：前端防线

### 1. 全局错误处理器（`main.js`）

- `app.config.errorHandler` —— 兜住组件内异常，**带上组件名与生命周期阶段**
  （如 `GraphCanvas` + `render function`），这是定位问题的关键信息
- `installGlobalErrorHooks()` —— 兜住 `window.onerror`（含资源加载失败）
  与 `unhandledrejection`

### 2. 错误上报（`utils/errorReporter.js`）

此前前端报错只落在 `console` 与一个内存数组里：**刷新即丢，后端完全看不见**。

现在上报到 `POST /api/system/client-error`，写入操作审计。三条自我约束：

- **去重**：同一错误 30 秒内只报一次（避免错误循环刷爆）
- **限流**：每分钟最多 10 条
- **静默**：上报失败绝不抛错、绝不弹窗（错误处理本身不能成为新错误源）

实测：注入未捕获异常 + 未处理 Promise 拒绝 + 模拟组件异常，三条全部落库，
审计详情含 `source=vue` / `component=GraphCanvas` / `info=render function` / `route`。

### 3. 错误边界（`components/ErrorBoundary.vue`）

项目里**本来就有**这个组件，但从未被使用。现在包住全部 6 个视图：

- 局部崩溃 → 只有一个面板不可用，**其余界面（如左侧文件管理面板）仍可操作**
- 保留「立即重试 / 回到知识图谱 / 查看详情」

关键加固 —— **自动重试必须有次数上限**（默认 2 次）：
故障若是持续性的（如接口 500），无上限的定时重试会变成每 3 秒一次的
**错误震荡**：界面反复闪、后端被反复打、日志被刷满。
超过上限后暂停自动重试并明确告知用户。

实测：兜底下 UI 正常渲染，左侧面板仍可用；点「立即重试」后画布恢复正常。

### 4. 请求层加固（`api/index.js`）

- **错误分类**：`ApiError` 保留 `status` / `hint` / `requestId` / `code`，
  并提供 `isNetwork` / `isServerError` / `isGuard` 判断
  （此前所有失败都退化成「一个无法判断的字符串」）
- **可执行建议**：优先用后端返回的 `hint`；后端没给时按状态码补
  （401 → 口令失效；413 → 拆分文件；422 → 列出具体字段问题）
- **幂等重试**：仅对 GET，网络/5xx 失败自动重试 1 次（带退避），
  `client-error` 上报接口排除在外避免风暴
- **服务端异常上报**：5xx 自动上报，让前端看到的故障也进后台

## 六、UI 优化

### 1. 导航激活项对比度（真实缺陷）

| | 修前 | 修后 |
|---|---|---|
| 文字色 | `--accent-light` `#6E8FAD` | `--accent-strong` `#3D5A75` |
| 底色 | `--bg-tertiary` `#EFE8DF` | `--accent-soft`（10% 品牌色） |
| **对比度** | **2.79 : 1** | **约 5.9 : 1** |

2.79:1 连 WCAG 大字号的 3:1 都不到，正常字号要求 4.5:1 —— 当前页几乎看不清。
另外叠加内描边（`inset box-shadow`），**不单靠颜色区分当前页**，色觉障碍用户也能分辨。

非激活页签也从 `--text-muted`（约 2.4:1）提到 `--text-secondary`（约 4.5:1）
—— 导航是主要入口，不该用装饰性灰。

### 2. 键盘可达性（此前为零）

- 全站 `:focus-visible` 焦点环（2px 品牌色 + 2px offset）
  —— 只在键盘导航时出现，鼠标点击不显示，兼顾可达性与视觉整洁
  此前纯键盘用户**完全无法判断焦点在哪**
- 导航页签补齐 `role="tablist"` / `role="tab"` / `aria-selected` /
  `aria-controls`，图标按钮补 `aria-label`
- **快捷键 `Ctrl/⌘ + 1~6`** 切页签（正在输入框内时不劫持）
- 页签上显示极淡的快捷键徽标，悬停/聚焦/激活时显现，帮助发现

### 3. 动效降级（此前为零）

`@media (prefers-reduced-motion: reduce)` 关闭全部动画与过渡。
对前庭功能敏感的用户开启该系统设置后，动效会引发不适 ——
这不是偏好，是明确的用户意图。

### 4. 导航溢出

6 个页签在窄窗口下会挤压右侧按钮。改为横向滚动（`overflow-x: auto` +
隐藏滚动条 + `flex-shrink: 0` + `white-space: nowrap` 防文字换行导致高度跳动），
并在切换页签时把激活项 `scrollIntoView` 滚入可视区。

### 5. 后台新增「系统自检」页签

把体检结果搬到界面上（`/api/system/doctor`），11 项逐条展示：
状态图标 + 名称 + 详情 + **可执行建议（品牌色单独成行）** + 耗时。
不单靠颜色传达状态：每行左侧有 3px 色条（通过/警告/错误）。
打开后台即自动体检，也可手动「重新体检」。

## 七、实测汇总

### 防线有效性

| 场景 | 结果 |
|---|---|
| 异常分类 | `no such column` → 表结构不一致 ✓（修复前误报为「数据库被占用」） |
| 未捕获 `IndexError` | HTTP 500 + `code=out_of_range` + request_id + 建议 ✓ |
| 未捕获 `KeyError` | HTTP 500 + `code=missing_key` + 建议 ✓ |
| 参数校验失败 | HTTP 422 + 字段级说明 `text: Input should be a valid string` ✓ |
| 404 | 结构化（含 request_id），同时保留 `detail` 兼容旧前端 ✓ |
| 响应头 | `X-Request-ID` / `X-Elapsed-Ms` 均注入 ✓ |
| 前端错误上报 | 3 类错误（window / promise / vue）全部落审计，含组件名与阶段 ✓ |
| 错误边界 | 兜底 UI 渲染正常，**左侧面板仍可用**；重试可恢复 ✓ |
| `limit=-1` | 修复前返回整表 → 修复后返回默认 30 条 ✓ |

### 体检结果（正式库当前）

```
11 项：通过 9 · 警告 2 · 错误 0

! 依赖完整性   可选依赖缺失：本地语义向量(sentence_transformers)
! 关键配置     后台口令仍是默认值
```

两条警告都是**真实且需要你决定**的事项，不是误报。

## 九、有价值的边界经验（供后续维护参考）

1. **`except: pass` 是 bug 的温床**。它让「功能静默降级」和「正常」看起来一样。
   向量编码失败降级 TF-IDF 就是典型：不报错、无日志，只有关联质量悄悄变差。

2. **越具体的判断越要放前面**。异常分类里类型匹配先于报文匹配，导致
   `no such column` 被误判成「数据库被占用」，指向了完全错误的排查方向。

3. **`min(x, MAX)` 不是边界防护**。它只挡上限，负数会原样透传，
   而 SQLite 的 `LIMIT -1` 是「不限制」——防护要写 `clamp(low, high)` 而不是 `min(high)`。

4. **自动重试必须封顶**。持续性故障 + 无限重试 = 错误震荡，
   比直接失败更糟（界面闪烁 + 后端被打 + 日志刷满）。

5. **相对路径解析要收敛到单一来源**。同一份配置在 3 个文件里各写一遍
   `dirname(dirname(__file__))`，因为文件层级不同就会算出不同目录，
   而且**两处都"能用"**，只在特定功能上表现为 404。

6. **兜底逻辑本身必须绝不抛异常**。`describe_exception`、`log_event`、
   `reportClientError` 全部 try 包裹且静默失败 ——
   错误处理链路再出错，会掩盖真正的错误。

## 十、本轮未做（如实说明）

- **未建统一的骨架屏/空态组件**。目前各视图的空态各写各的（部分用 `el-empty`）。
  建议后续抽一个 `AppSkeleton` / `AppEmpty`，统一尺寸、间距与文案语气。
- **前端未接 ESLint/Prettier**。当前依赖「构建能过 + 体检脚本」，没有代码风格与
  常见陷阱（如 `==`、未使用变量、`v-for` 缺 key）的静态约束。
  若要接，建议 `eslint-plugin-vue` + 在体检脚本里加一步 `npm run lint`。
- **未加自动化回归测试**。核心链路（上传 → 切割 → 候选 → 判定 → 入库）
  目前靠手工脚本验证。建议把本轮用到的 TestClient 脚本固化成 `backend/tests/`。
- **`sentence_transformers` 未安装**，向量走的是 TF-IDF 兜底（体检已提示）。
  如需要更准的语义向量，装上即可，无需改代码。
- **后台口令仍是 `kg-admin`** —— 请在 `backend/.env` 改掉。
