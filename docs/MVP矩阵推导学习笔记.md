# MVP 矩阵推导学习笔记

## 〇、终点目标

```
gl_Position = P × V × M × v   （v 是模型空间顶点，列向量，从右往左作用）
```

顶点经历 4 个空间：**模型空间 →(M)→ 世界空间 →(V)→ 相机空间 →(P)→ 裁剪空间 →(÷w)→ NDC → 屏幕**。

## 一、数学基础：为什么必须用 4×4 矩阵（齐次坐标）

**痛点**：平移 `x' = x + t` 是加法，3×3 矩阵只能表达线性变换（旋转/缩放/错切）。要统一成矩阵乘法，必须把 3D 点升维到 4D 齐次坐标：

```
点   (x, y, z) → (x, y, z, 1)     w = 1：位置
向量 (x, y, z) → (x, y, z, 0)     w = 0：方向（平移无效）
```

**齐次坐标几何本质**：(x, y, z, w) 与 (x/w, y/w, z/w, 1) 是同一个点——乘以任意非零常数不变。这个多余自由度正是透视投影的基石：深度塞进 w，最后统一除以 w，近大远小自然产生。

平移矩阵：

```
T = [ 1  0  0  tx ]
    [ 0  1  0  ty ]
    [ 0  0  1  tz ]
    [ 0  0  0  1  ]
```

## 二、M 模型矩阵：模型空间 → 世界空间

**M = T · R · S**（缩放 → 旋转 → 平移）

```
S = diag(sx, sy, sz, 1)    R = 3×3 旋转放左上角    T = 平移矩阵
```

**为什么是这个顺序？** 作用时从右往左读：`v_world = T·(R·(S·v))`。先缩放，再绕**模型原点**旋转，最后平移到世界位置。先平移再旋转会让旋转中心变成世界原点，物体绕世界原点"甩"出去。

> 物理引擎呼应：box2d-lite 每帧更新的 position + rotation 填进 R 和 T，就是这里的 M。

## 三、V 视图矩阵：世界空间 → 相机空间

**目标**：把相机搬到原点，视线朝 −z，上方 +y。

**输入**：eye(E)、target(T)、up(U)。

**第一步：构建相机正交基**（右手系）：

```
f = normalize(T − E)           前向
s = normalize(cross(f, U))     右向（叉乘保证与 f 垂直）
u = cross(s, f)                真正的上（U 不严格垂直时正交化）
```

**第二步：合成矩阵**（先平移相机到原点，再旋转对齐坐标轴）：

```
V = [ s.x  s.y  s.z  −dot(s, E) ]
    [ u.x  u.y  u.z  −dot(u, E) ]
    [ −f.x −f.y −f.z  dot(f, E) ]
    [ 0    0    0    1          ]
```

- 前三行 = 相机基向量（s, u, −f）；第三行取 `−f` 因为 OpenGL 相机朝 −z 看
- 最后一列 = 先平移 −E 再旋转的合成：平移列 = R·(−E)，x 分量 = −dot(s, E)

## 四、P 投影矩阵：相机空间 → 裁剪空间

投影把视锥体映射成裁剪立方体 [−w, w]³，GPU 除以 w 得 NDC [−1, 1]³。

### 4.1 正交投影（无近大远小）

```
P_ortho = [ 2/(r−l)  0        0       −(r+l)/(r−l) ]
          [ 0        2/(t−b)  0       −(t+b)/(t−b) ]
          [ 0        0       −2/(f−n) −(f+n)/(f−n) ]
          [ 0        0        0        1           ]
```

每行 = "平移居中 + 缩放归一到 [−1,1]"。

### 4.2 透视投影：相似三角形出发（核心推导）

参数：近平面 `n`、远平面 `f`、垂直视场角 `fovy`、宽高比 `aspect`；`f = 1/tan(fovy/2)`。

**相似三角形**（侧视图）：

```
              近平面(z=−n)          物体点 P(x, y, z)
  相机 O ──────────●──────────────●
  (原点)          |              |
                  |←— x_near —→|   x_near / x = n / (−z)
```

投影位置：`x_near = x·n/(−z)`，`y_near = y·n/(−z)`。

近平面的半高 = n·tan(fovy/2) = n/f，半宽 = 半高·aspect → NDC：

```
x_ndc = x·f / (aspect·(−z))
y_ndc = y·f / (−z)
```

**关键观察：都除以了 (−z)！** 让矩阵算出的 `w_clip = −z`，GPU 透视除法自动完成近大远小。

**构造 P 矩阵**：

```
P = [ f/aspect  0   0   0 ]
    [ 0         f   0   0 ]
    [ 0         0   A   B ]
    [ 0         0  −1   0 ]
```

- x_clip = f/aspect·x（aspect 修正），y_clip = f·y
- **w_clip = −z**
- z_clip = A·z + B：由映射 [−n, −f] → [−1, 1] 解出：

```
z_ndc = (A·z + B)/(−z) = −A − B/z
近平面 z=−n: −A + B/n = −1
远平面 z=−f: −A + B/f =  1
⇒ A = (f+n)/(n−f)    B = 2·f·n/(n−f)
```

**验证**：x_ndc = f·x/(aspect·(−z)) ✓ 与相似三角形推导一致。

### 4.3 深度非线性（面试高频）

`z_ndc = −A − B/z`：深度是 1/z 的函数。

- 近处：精度高（z 变化一点，z_ndc 变化大）
- 远处：精度低（z 变化很大，z_ndc 才动一点）→ 远处物体容易 **z-fighting**（深度冲突闪烁）

缓解：对数深度、更高位深深度缓冲、split depth。

## 五、合成：为什么是 P·V·M（右乘顺序）

列向量约定下，离顶点最近（最右）的矩阵最先作用：M 先、V 次、P 最后。工程上每帧 CPU 预乘 `MVP = P·V·M` 只传一个 uniform：

```glsl
gl_Position = uMVP * vec4(aPos, 1.0);
```

## 六、数字例子（完整走一遍）

顶点 `v = (1, 0, 0)`：缩放 2 → 绕 z 转 90° → 平移 (1,0,0) → 相机在 (0,0,5) 看原点 → 透视（f=1, aspect=1, n=1, f=100）：

| 阶段 | 变换 | 结果 |
|---|---|---|
| 模型空间 | S·v | (2, 0, 0) |
| 旋转后 | R·(S·v) | (0, 2, 0) |
| 世界空间 | T·(…) | (1, 2, 0) |
| 相机空间 | V·(…) | 约 (1, 2, −5) |
| 裁剪空间 | P·(…) | (1, 2, A·(−5)+B, 5) |
| NDC | ÷w | (0.2, 0.4, z_ndc) |
| 屏幕 | viewport 映射 | 像素 |

## 七、面试必答三点

1. **为什么 w 分量？** ① 平移无法用 3×3 表达，升维后统一成矩阵乘法；② w 为透视除法预留位置，近大远小靠它实现。
2. **M 为什么是 T·R·S？** 矩阵右乘先作用；旋转/缩放以模型自身原点为基准，顺序错了物体绕世界原点旋转。
3. **透视矩阵的 z 为什么非线性？** `z_ndc = −A − B/z`，近处精度高远处精度低——深度缓冲区 z-fighting 的根因。
