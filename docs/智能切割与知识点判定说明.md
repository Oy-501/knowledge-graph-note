# 智能切割 · 知识点判定 · 后台管理 · 个人主页

> 本轮新增四件事：① 大文件由系统**自己切割**（不再拒绝，且保证知识点读取完整）；
> ② 抽出的知识点**存进候选池**并做**智能判定**；③ 判定可**联网交叉验证**；
> ④ 提供**后台管理**（看每条判断的依据、逐条裁决、回溯所有用户操作）与**个人主页**（头像 + 自定义背景）。

---

## 一、智能切割：切了也不丢知识点

### 为什么能"切而不丢"

| 机制 | 做法 | 解决什么 |
|---|---|---|
| **只在结构边界落刀** | 优先在 `#` 标题行之前切，其次在空行段落之间切，最后才按行数强制切 | 绝不在段落中间切断一句话，而句子里往往就是知识点 |
| **标题上下文继承** | 每个分片带上**进入该片时**的祖先标题路径（如 `# 前端开发 > ## Vue`）作为前缀 | 概念横跨两片时，抽取仍能拿到正确的领域/层级语境 |
| **相邻片重叠** | 默认重叠 2 行 | 落在刀口上的那句话不会被两片各丢一半；重复抽出的知识点由 `merge_same_entity` 自然去重 |
| **分片可追溯** | 每片记录 index / 起止行号 / 标题路径 / 切点性质，写入 `Node.chunk_index` | 后台与审计能还原"这个知识点来自原文第几片、第几行" |

### 实测（16027 行 / 1.14MB 结构化文档）

```
切点：片1 1-6000行（标题边界）· 片2 5999-11997行（标题边界）· 片3 11996-16027行（文末）
校验：切点 100% 落在标题或段落边界；行覆盖完整（16027/16027，无缺行）
结果：上传 0.14s → 解析 21s → 1200 个知识点（原方案会因上限只留 600 且截断）
```

### 配置

```ini
SPLIT_TARGET_LINES=6000      # 单片目标行数（也是触发切割的阈值）
SPLIT_TARGET_CHARS=1200000   # 单片目标字符数（≈1.1MB 纯文本）
SPLIT_MAX_PIECES=40          # 单文件最多切多少片
SPLIT_OVERLAP_LINES=2        # 相邻片重叠行数
MAX_NODES_PER_FILE_TOTAL=3000  # 切割后一个文件允许的知识点总量上限
```

## 二、候选知识点：先入池，再判真假

抽出的每个知识点都会写入 `knowledge_candidates`（候选池），字段包含：来源文件/第几片/行号、原文证据、
抽取置信度、判定分数、判定决定、**判定依据（证据链 JSON）**、判定阶段（自动/人工）、裁决人与备注。

这样做的价值：**抽取与采纳解耦** —— 抽取可以宽松（不漏），采纳必须严格（不错）。

---

## 三、智能判定：四路证据加权 + 分级处置

| 证据 | 具体看什么 | 权重示例 |
|---|---|---|
| ① 知识库一致性 | 是否命中知识库条目（规范名/别名）；描述与知识库定义是否一致（字符二元组相似度）；是否有关系桥接 | 命中 `+0.30`、定义一致 `+0.15`、**定义冲突 `-0.25`（并标记 conflict）**、无此条目 `-0.05` |
| ② 图谱证据 | 该节点是否被知识库概念锚定、已建立多少关联 | 有锚定 `+0.10`、有连线 `+0.05`、游离 `-0.05` |
| ③ 文本质量规则 | 标题是否像术语（编号开头 / 谓语片段 / 过长 / 过短）；描述长度；是否含定义性句式；关键词数量 | 标题正常 `+0.15`、谓语片段 `-0.35`、含定义句式 `+0.10`、描述过短 `-0.05` |
| ④ 联网证据 | 抓公开搜索结果，看标题/摘要是否提及该概念 | ≥2 条命中 `+0.15`、1 条 `+0.08`、未命中 `-0.05`、**不可用时记 0 并标注"未联网"** |

### 分级策略（可在 `.env` 调整）

```
score ≥ 0.80 且无冲突 → accept   建议采纳（可自动写入知识库）
score < 0.35          → reject   建议驳回
其余                  → pending  进后台待审队列，由管理员逐条确认
```

`verdict_reason` 会生成一句人类可读的结论，例如：

> 需人工确认（综合 0.43）。支持：标题形态正常（6 字，无编号/谓语片段）；有描述文本（31 字）；
> 描述含定义性句式；抽取到 11 个关键词。疑点：知识库中暂无该条目（新概念，需靠其他证据判断）。

### 联网判定的取舍（已与用户确认）

- **零配置**：直接抓公开搜索页（Bing / 搜狗 / 360 / 百度，按顺序尝试），不需要任何 API Key；
- **抗改版**：用「标题块 + 邻近文本」的通用提取，而不是写死站点选择器；全部失败时退化为全文关键词命中；
- **优雅降级**：抓不到就把 `web_status` 标记为 `unavailable`，判定只靠本地证据，并在理由里写明"未联网"；
- **预算保护**：单批判定最多联网 `VERDICT_MAX_WEB_CALLS`（默认 30）次，结果缓存 15 分钟，绝不整批卡在网络。

实测（本机网络）：

```
TypeScript      → 联网 ok（bing）· 5 条结果全部提及       → 正证据
Vue.js          → 联网 ok（bing）· 5 条结果全部提及       → 正证据
彩虹排序法内部实验 → 联网 ok（bing）· 0 条结果提及（自造概念）→ 负证据
```

## 四、后台管理（口令保护）

进入方式：顶部导航「后台管理」→ 输入口令（`.env` 的 `ADMIN_TOKEN`，默认 `kg-admin` 请尽快修改，
留空则关闭保护）。口令存在浏览器本地，所有后台接口都需要 `X-Admin-Token` 头。

| 标签页 | 内容 |
|---|---|
| **概览** | 规模卡片（用户/文件/知识点/连线/知识库条目/审计数）、候选判定分布、阈值说明、近 7 天操作分布、判定分数分布与人工复核率 |
| **知识点审阅** | 候选列表（按状态/判定/联网/关键词筛选）→ 点开详情看**完整证据链**（每条证据的类型/权重/说明/来源链接）与原文 → 采纳（写入知识库）/ 驳回 / 转待审；支持批量采纳/驳回与**重跑智能判定（含联网）** |
| **操作审计** | 所有操作台账：动作、来源（user/admin/system）、对象、**依据摘要**、耗时；点开看依据明细 JSON |
| **用户与文件** | 用户列表（数据量、操作数、最近活动）；文件列表（知识点数、候选判定分布、**切割/截断备注**） |

### "用户操作的根据"具体长什么样

| 动作 | 记下的依据 |
|---|---|
| `upload` | 文件行数/字符数、是否需要切割、**切割阈值与实测对比**、每片起止行与标题上下文 |
| `split` | 每片 index/行数/标题路径/切点性质（标题边界/段落边界/行数兜底）、切割规则说明 |
| `parse` | 每片抽了多少知识点、是否被截断、合并后的总数、生效的上限 |
| `verdict` | 判定分数、决定、逐条证据、联网状态、生效阈值、若入库则记知识库条目 id |
| `review` | 裁决动作、裁决前后的状态对比、自动判定结果（供对比）、备注、是否覆盖了自动判定 |
| `delete_file` / `delete_candidate` | 删了什么、连带清除了哪些数据 |
| `profile_upload` / `profile_update` | 上传了什么文件、替换了哪个旧文件、图片校验方式、配置变更前后 |

## 五、个人主页

- **头像与背景图上传到服务端**（`backend/uploads/{avatars|backgrounds}/`，通过 `/uploads/...` 静态访问），
  换设备/换浏览器依然生效（此前背景只存在浏览器本地）；
- 校验：大小 ≤ `MAX_IMAGE_MB`（5MB）、类型按**文件头魔数**判断（JPG/PNG/GIF/WebP），不信任扩展名；文件名随机化；
- 背景参数：不透明度、模糊、作用范围（全局 / 仅工作台），保存后可一键"应用到界面"（复用原有背景系统）；
- 替换或移除背景时自动清理旧文件；
- 页面上还有「我的数据」概览（文件/知识点/候选/待审/知识库条目/操作记录）。

## 八、已知限制（如实说明）

1. **联网判定依赖本机网络**：若网络屏蔽了搜索引擎，会自动降级为"未联网"，此时判定只靠知识库 + 图谱 + 规则；
2. **搜索引擎可能改版**：已用通用提取 + 全文兜底，但仍可能出现结果质量下降（可在 `web_probe._PROVIDERS` 里调整顺序或增加来源）；
3. **判定是启发式，不是真理**：它只负责把明显的对/错筛出来（真概念 5/5 命中、自造概念 0/5 命中），
   中间地带一律进人工队列，**最终采纳权在管理员**；
4. **切割有单片上限**：单片仍受 `MAX_NODES_PER_FILE`（600）保护，超长文档靠"多片累计"
   （总量 `MAX_NODES_PER_FILE_TOTAL`，默认 3000）；再大建议按主题拆成多个文件；
5. **审计会截断**：`AUDIT_KEEP_ROWS` 之后清理最旧记录；后台口令是单一口令、无账号体系（单机单用户场景够用）。
