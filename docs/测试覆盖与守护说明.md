# 后端测试与守护说明

这是后端测试套件的**使用与维护说明**。改动代码前想知道「有没有测试守着我改的东西」，
看这里；想知道「某次改了什么」，看 `更新日志.md`。

---

## 一、怎么跑

```bash
cd backend
py -m pytest                       # 全量：224 条 / 约 44 秒
py -m pytest -m "not slow_model"   # 跳过真语义模型那 8 条（省约 22 秒）
py -m pytest tests/test_parser.py  # 只跑一个模块
py tests/verify_guards.py          # 反向验证：23 项破坏，确认测试真的守得住（约 4 分钟）

# 界面功能验证（真实浏览器，零第三方依赖；需要一套独立的前后端）
node backend/tests/ui_functional_check.mjs \
     --url http://127.0.0.1:5174 --api http://127.0.0.1:8096/api
```

依赖在 `requirements-dev.txt`，**与生产依赖分开**，不进镜像。

### 界面检查需要一套独立的前后端

它会**真的注册账号、真的上传文件**，绝不能指向正在使用的实例（那会往用户的库里塞数据）。
起法：

```bash
# 后端：临时库 + 开放注册
cd backend && SQLITE_PATH="<绝对路径>/uitest.db" DB_MODE=sqlite \
  REGISTRATION_OPEN=true ADMIN_TOKEN=uitest-token VERDICT_USE_WEB=false \
  py -m uvicorn app.main:app --port 8096

# 前端：另起一个 vite，用环境变量把 API 指过去（Vite 会读进程环境里的 VITE_* 变量）
cd kg-vue3 && VITE_API_BASE=http://127.0.0.1:8096/api npx vite --port 5174 --strictPort
```

脚本用 Node 22 **内置的全局 `WebSocket`** 讲 Chrome DevTools Protocol，
不依赖 playwright/puppeteer；只需要本机装了 Chrome（默认路径可用 `--chrome` 覆盖）。
每次跑会用全新的浏览器 profile，所以会话不跨次保留。

## 二、两道安全闸门（改夹具前必读）

| 闸门 | 怎么实现的 | 不这么做的后果 |
|---|---|---|
| 测试库隔离 | conftest 在 `import app` **之前**设 `SQLITE_PATH` 指向系统临时目录 | 测试写到正式库 `backend/kg.db`，损伤不可逆且当场看不出来 |
| 导出目录隔离 | 同上，设 `EXPORT_DIR` | 导出目录按 mtime 只留最近 N 个，跑一次导出用例就把用户自己的产物挤掉 |

两条**都有专门用例断言**（`test_smoke.py::test_not_pointing_at_production_db`、
`test_summary_export.py::test_exports_land_in_the_configured_directory`）——
闸门不能只靠「夹具写对了」，得有东西在它失效时喊出来。

另外两条夹具约定：

- 用例间清理**不要手写表顺序**，取 `Base.metadata.sorted_tables` 逆序（父在前 → 逆序即子在前）。
  手写漏过一次，报错摊在夹具上，看起来像「测试环境坏了」而不是「顺序写错了」。
- **不要用 pytest 的 `tmp_path`**，用 conftest 的 `workdir`。`tmp_path` 会在会话开始时
  清理历史临时目录，而本机安全删除钩子对批量删除（>50 条）整批拒绝 ——
  结果是**测试全过、退出码却是失败**，在 CI 里会被判成红灯。

## 三、守住了什么

| 模块 | 守什么 | 为什么值得守 |
|---|---|---|
| `test_smoke.py` | 套件地基：连的不是正式库；相对路径解析正确 | 地基错了，后面所有结论都不可信 |
| `test_paging.py` | `clamp_paging` 的边界 | `?limit=-1` 在 SQLite 里等于「不限行数」，且状态码是 200 |
| `test_vector_engine.py` | 中文按字切词、引擎指纹、陈旧与损坏分类 | 曾按空白切词 → 中文相似度恒为 0，不报错只失效 |
| `test_vector_model.py` | 真语义模型路径（维度、归一化、区分度地板） | 其余用例固定走降级引擎，真模型路径曾经零覆盖 |
| `test_kb_index.py` | 内容指纹缓存与失效 | 计数级指纹对「改一条已有条目」不敏感，会一直供旧数据 |
| `test_inference.py` | 连线桥接标记由依据推导 | 标记写死过一次，统计量变成「哪段代码写的」 |
| `test_parser.py` | 句子残骸不被当成知识点 | 残骸会一路污染枢纽榜，最后上学习主线 |
| `test_summary_export.py` | 六种导出、去重、参数一致、PPT 反查、空节说明 | 这些是**最终交付物**，出错在测试里看不出来 |
| `test_auth_guard.py` | 401/403 语义、豁免名单、fail-closed | 401/403 混用会把已登录用户误踢回登录页 |
| `test_files_purge.py` | 删文件清干净所有子表 | 外键报错点在 `DELETE FROM files`，看不出是哪张子表 |
| `test_api_contract.py` | 错误信封、request_id 净化、401 也带 CORS 头 | CORS 缺失只表现为「浏览器连不上」，curl 一切正常 |
| `test_auth_recovery.py` | 恢复码只存哈希、重置后轮换且吊销会话、错码不泄露用户是否存在、独立限流、建号/重置的越权边界 | 这几条错得很安静：功能看着正常，安全性已经没了 |
| `test_system_doctor.py` | 自检的报告完整性（不漏报） | 自检漏报比误报危险：看到「一切正常」就不会再查 |
| `test_socket_layer.py` | 真实 TCP：keep-alive、畸形报文、慢客户端、分帧 | 其余用例走 ASGI 内存传输，**完全不经过 TCP** |
| `test_functional_journeys.py` | **完整用户旅程**：初始化/登录 → 上传→解析→图谱→总结→导出→删除，每步断言中间产物；含**登录会话通道**全程（主通道不能是二等公民） | 单模块全绿、契约全绿，功能仍可能整条断掉 |
| `ui_functional_check.mjs`（脚本） | **真实浏览器**：登录门禁、页签、上传、总结出图、导出、权限提示 | 后端 200+ 条用例一条都没打开过界面 |

## 四、反向验证：测试真的守得住吗

**一套全绿的测试可能什么都没守住。** 只要断言写得不够松，破坏代码它照样绿；
这种「假绿」比没有测试更危险。

`tests/verify_guards.py` 逐个**故意破坏**被守护的逻辑，确认对应用例真的失败，再还原。
当前 23 项，覆盖上表里每条关键不变量。

其中 4 项**只打中 `test_functional_journeys.py`**，共同特征是：破坏之后**状态码仍然是 200**，
只有去断言中间产物才看得见（上传 200 但没解析出节点、删文件后节点残留、
上传的内容搜不到、写守卫不认会话）。这正是功能测试这一层存在的理由 ——
只测模块不变量的用例，在被破坏时**每一条都还是绿的**。

跑完必须满足两件事，缺一不可：

1. 每一项破坏**都被抓住**（对应用例失败）；
2. **还原后基线恢复全绿**（否则后面的「已抓住」都不算数）。

### 设计要点（踩过坑才有）

- **还原用「把原文写回」，不要 `shutil.move`。** move 在目标已存在时走的是
  「复制 + `unlink(备份)`」，本机钩子会拦 `unlink` → 异常正好抛在 `finally` 里。
  一个专门用来「先破坏再还原」的脚本，最不该有的失败模式就是还原到一半炸掉。
- **备份不落盘**（原文已在内存里）。落盘的 `.bak` 删不掉，跑一轮就在源码目录留十几个。
- **破坏的替换目标不要指向仓库目录**，指到系统临时目录 —— 否则代码还原了目录却留下了。
- **锚点必须唯一**（跑前校验 `count == 1`）；锚点找不到要**报错**而不是静默跳过 ——
  静默跳过会让一项破坏悄悄消失，看着还是「全部通过」。
- **取 pytest 的汇总行**，而且**要取得到**。这里踩过一个很隐蔽的坑：`pytest.ini` 的
  `addopts` 里已经有 `-q`，脚本又传了一个 `-q` → 变成 `-qq`，而 pytest 在 `-qq` 下
  **不打印结尾的统计行**。于是「取汇总行」永远取不到，静默回退到最后一行 ——
  看着像在工作，实际读的是别的行（比如 `-- Docs: …`），读起来像是用例挂了。
  现在只在 stdout 里找带数字的统计行，并把首个失败用例名一起带上。
- **结语要与退出码一致**：曾经打印「还原后恢复全绿」而实际基线是红的 —— 自己给自己盖章。

### 关键断言要配负向对照

例如 `test_socket_layer.py` 断言「两次请求复用同一条 socket」时，
另有一条用例用 `Connection: close` 让服务端关连接，验证客户端**确实会丢弃 socket**。
没有这条对照，前一条断言可能是恒真的（`http.client` 在对端关闭时会自己重连，
「两次都 200」根本证明不了长连接生效）。

同理，噪声判据要量**命中与误杀两个数**：`looks_like_clause` 在 36 条真实语料上实测
命中 3 条残骸、误杀 0 个术语。缺了误杀那一半，「把标题全清空」也是 100% 命中。

## 五、加新测试时的三条

1. **锚在真实入口或完整管线上**，别只测中间函数。
   抓过两次同类盲区：只测纯函数没测**调用点**（标记在调用点被写死）、
   只测 `extract_entity` 没测**完整抽取管线**（后面还有句子分类与标题兜底把关，
   单测中间态会高估问题）。
2. **断言「关系」而不是「数值」**，除非那是质量地板。
   分数会随模型版本变，钉死数值只会变成噪音；但「区分度必须 > 0.30」这种地板要钉住 ——
   实测真模型 +0.591、降级 +0.161，取 0.15 的话模型静默降级照样绿灯。
3. **新增守护逻辑后，同步加一条反向验证破坏项**，并在 `verify_guards.py` 里更新锚点。
   破坏项数量 = 你打算守住的规则数量；对不上就说明有漂移。

## 六、已知未覆盖

- **真模型路径默认会跑**（约 22 秒），但**模型不可用时是 skip 而不是 pass**，
  skip 会在输出里显式列出原因。
- 测试不覆盖 Electron 外壳（`main.js`/`preload.js`）与前端组件；前端只有
  `kg-vue3/tests/` 下两个手写用例，未纳入 pytest。
- 性能与稳定性测试不在这里，见 `稳定性测试报告.md`、`性能测试与调优报告.md`，
  脚本在 `.tmp-verify/`（gitignored，属于一次性工具而非常驻资产）。
